Style properties reference

Every Markdown element is styled through the markdownStyle { } DSL. This page lists each block you can open and the properties it takes. For how a style reaches a component and how layering works, see MarkdownTheme.

The markdownStyle builder​

A style is a set of overrides. Open only the blocks you want to change, while everything else keeps the default listed below.

val AppMarkdownStyle = markdownStyle {
  paragraph {
    fontSize = 16.sp
    lineHeight = 26.sp
  }
  h1 { color = Color(0xFF111827) }
  codeBlock {
    backgroundColor = Color(0xFF1F2937)
    cornerRadius = 8.dp
  }
}

The available blocks:

BlockApplies to
paragraphBody text
h1 … h6Headings, each level styled independently
blockquoteBlock quotes, plus admonitions { } geometry for GitHub alerts
listOrdered and unordered lists, including their markers
taskListTask list checkboxes
codeBlockFenced code blocks
codeInline code
linkLinks and autolinks
strongBold text
emphasisItalic text
strikethroughStruck-through text
underlineUnderlined text (needs MarkdownOptions(underline = true))
superscriptSuperscript (needs MarkdownOptions(superscript = true))
subscriptSubscript (needs MarkdownOptions(subscript = true))
highlightHighlighted text (needs MarkdownOptions(highlight = true))
imageBlock images
inlineImageInline images
thematicBreakHorizontal rules
tableGFM tables, header row and cells
spoilerThe overlay that hides spoiler text until it is tapped

Values use Compose types throughout: Color, Dp for lengths, TextUnit (sp) for text metrics, plus FontFamily, FontWeight, FontStyle, TextAlign, TextDecoration, and Alignment.Horizontal.

The optional math artifact adds two more blocks, math { } and inlineMath { }, for LaTeX formulas. They are documented with the plugin in LaTeX math. The optional code-highlight artifact adds codeHighlight { }, for the token colors of highlighted code blocks; see Code highlighting.

caution

fontSize and lineHeight must be given in sp. A TextUnit of any other type (em, or TextUnit.Unspecified) makes the style throw an IllegalArgumentException when it is resolved.

FontWeight is bucketed to the four weights the text layer draws: below Medium renders as normal (400), then Medium (500), SemiBold (600), and Bold and heavier as bold (700). FontWeight.Light and FontWeight.Black therefore look the same as Normal and Bold.

Style inheritance​

Block styles are self-contained: a paragraph and an h1 each carry their own font size, color, line height, and margins, and one never falls back to the other.

Inline styles are partial by design. strong, emphasis, strikethrough, underline, and link set only the handful of properties that make them distinct, and everything else - size, line height, and by default the color - is inherited from whatever block the text sits in. Bold text in a heading is therefore heading-sized, while bold text in a paragraph is paragraph-sized, with no configuration.

That is why several inline properties default to "inherited" rather than a value. Setting one pins it everywhere the element appears:

markdownStyle {
  strong { color = Color.Red } // bold is red in headings, paragraphs, quotes alike
}

Leave it unset to keep bold following its surroundings.

Layering with merge​

MarkdownStyle.merge { } adds a layer on top of an existing style rather than replacing it, so variants stay expressed as differences:

val Base = markdownStyle {
  paragraph { fontSize = 16.sp }
  link { textDecoration = TextDecoration.None }
}

val Compact = Base.merge { paragraph { marginBottom = 8.dp } }

See MarkdownStyle.merge for the details.

Dark mode​

The defaults below are a light palette - the library does not swap them automatically. If you're coming from iOS, where the default theme uses system colors and adapts to dark mode by itself, rememberMaterialMarkdownStyle is how you get the same behavior here. Supply the colors for the current theme yourself, either from the Material color scheme:

MarkdownTheme(style = rememberMaterialMarkdownStyle()) {
  Content()
}

…or as two hoisted variants of one base style, picked by isSystemInDarkTheme():

MarkdownTheme(style = if (isSystemInDarkTheme()) DarkMarkdownStyle else LightMarkdownStyle) {
  Content()
}

A code block that follows the theme needs its text color set alongside the background, since the default text color is made for the default dark block. With code highlighting, the token palette is made for a dark block too, so a light code block needs codeHighlight { } colors as well.

rememberMaterialMarkdownStyle rebuilds the style when the color scheme changes. If you pick your own tokens instead, read MaterialTheme.colorScheme first and build the style in remember, keyed on it.

admonitions​

A blockquote opening with > [!NOTE], > [!TIP], > [!IMPORTANT], > [!WARNING], or > [!CAUTION] renders as a themed callout with a tinted icon and a bold title. Admonitions nest under blockquote because they inherit its geometry - border width, gap, font, and spacing all come from the block above - and override only colors.

markdownStyle {
  blockquote {
    admonitions {
      warning {
        color = Color(0xFF9A6700)
        backgroundColor = Color(0xFFFFF8C5)
      }
      caution { color = Color(0xFFCF222E) }
    }
  }
}

Each of note, tip, important, warning, and caution takes:

PropertyTypeDefaultDescription
colorColorPer type, belowTints the accent bar, the title, and the icon
backgroundColorColorUnsetBackground fill. Unset means the callout is drawn unfilled

Default color per type, matching GitHub's alert palette:

TypeDefault color
note#0969DA
tip#1A7F37
important#8250DF
warning#9A6700
caution#CF222E

Types you omit keep their defaults, and within a type an omitted property falls back the same way. The title is always bold, whatever fontWeight the blockquote carries.

note

Requires MarkdownOptions(admonitions = true), which is off by default. Without it the marker is literal text in an ordinary quote and these styles do not apply.

A code block set to scroll also has a header bar, with the language name and a copy button. The header has no properties of its own: the label and copy icon are drawn in color at reduced opacity, the label at 85% of fontSize, and the line under the header in a fainter color. backgroundColor, borderColor, borderWidth, and cornerRadius frame the header and code as one box.

With the optional code-highlight artifact, tokens inside the block are recolored by language; color stays the color of everything the highlighter leaves uncolored. Token colors have their own codeHighlight block.

markdownStyle {
  codeBlock {
    fontSize = 13.sp
    backgroundColor = Color(0xFF0D1117)
    borderColor = Color(0xFF30363D)
    cornerRadius = 10.dp
    padding = 14.dp
  }
}

table​

GFM pipe tables - the body text, the header row, and the grid.

Header cells ignore fontWeight and are bold by default: they use the cell fontFamily in bold (the system bold face when no family is set). headerFontFamily replaces that face and is used as given, so pass a bold family if you want the header to stay bold.
